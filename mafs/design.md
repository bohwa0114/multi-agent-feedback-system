# MAFS 시스템 설계 지침서

Multi-Agent Writing Feedback System  
초5~중3 논술형 글쓰기 피드백 자동 생성 다중 에이전트 시스템

---

## 1. 시스템 개요

### 1.1 시스템 목적

MAFS(Multi-Agent Writing Feedback System)는 초등5학년~중학교3학년의 논술형 글쓰기 과제에 대해 교육적으로 우수한 피드백을 자동 생성하는 다중 에이전트 시스템이다. AI Hub 논술형 글쓰기 평가 데이터(dataSetSn=71819)의 초5~중3 국어·사회 에세이를 입력으로 받아, 과제수행·내용·조직·표현 네 영역별 피드백을 병렬로 생성하고 통합한다.

※ **데이터 범위**: AI Hub 데이터 중 초5~중3 국어·사회 10개 폴더를 사용한다. 과학 폴더(초5 과학·중3 과학)는 제외한다. 이로써 5(학년)×2(교과) 완전 균형 설계가 구성된다.

| 학년 | 국어 | 사회 |
|------|------|------|
| 초5 | TL_1._초5_1._국어 | TL_1._초5_3._사회 |
| 초6 | TL_2._초6_1._국어 | TL_2._초6_3._사회 |
| 중1 | TL_3._중1_1._국어 | TL_3._중1_3._사회 |
| 중2 | TL_4._중2_1._국어 | TL_4._중2_3._사회 |
| 중3 | TL_5._중3_1._국어 | TL_5._중3_3._사회 |

고등학교 데이터 및 과학 교과는 제외한다.

### 1.2 두 가지 핵심 차별점

**차별점 1. MISCA 모형 기반 교육적 검증**  
기존 AEF 시스템의 검증 기준은 피드백의 언어적 품질("이 피드백이 잘 쓰였는가")에 초점을 맞추는 반면, MAFS는 Panadero & Lipnevich(2022)의 MISCA 피드백 모형에 근거하여 피드백의 교육적 효과성("이 피드백이 교육적으로 올바른가")을 검증한다.

**차별점 2. 동적 가중치 기반 맞춤형 피드백**  
학생 에세이에서 자동 진단된 취약 신호와 AI Hub 전문가 피드백 데이터에서 학습한 영역별 가중치 패턴을 결합하여 최종 가중치를 동적으로 산출한다. Vygotsky(1978)의 ZPD 개념에 근거하여 학생 개인의 근접발달영역을 반영한 맞춤형 피드백을 생성한다.

※ 가중치 산출 방식: LLM이 에세이를 먼저 스스로 읽고 영역별 취약 신호를 판단한 뒤, 전문가 피드백 데이터 학습 결과(목적별·취약 패턴별 평균 분포)를 참고하여 최종 가중치를 결정한다. 학습 데이터는 맹목적으로 따르지 않고 LLM의 독자적 판단과 결합한다.

**차별점 3. Context Engineering 기반 에이전트 컨텍스트 설계**  
MAFS는 각 에이전트가 수신하는 컨텍스트를 역할에 따라 정밀하게 설계한다. 검증 에이전트는 매니저의 진단·추론 결과를 수신하지 않아 확증 편향(confirmation bias)을 차단하고, 4개 병렬 에이전트는 진단 결과 없이 에세이만 읽어 영역별 독립 분석을 보장한다. 각 단계가 이전 단계 출력을 선택적으로 누적하는 단계적 컨텍스트 구조(progressive context accumulation)와, AI Hub 전문가 데이터에서 학습된 도메인 지식을 진단 단계 컨텍스트에 주입하는 방식으로 LLM의 추론 품질을 높인다.

### 1.3 구현 환경

- 프레임워크: Google ADK (Agent Development Kit) — 4개 병렬 에이전트 실행에 활용
- 오케스트레이션: Python 하드코딩 (ADK LlmAgent 매니저 미사용)
- 인터페이스: 배치 처리 (`batch_run.py`, `evaluate/`)
- 개발 환경: Python, VS Code
- 데이터: AI Hub 논술형 글쓰기 평가 데이터 (학생 에세이 + 전문가 피드백 활용)

### 1.4 시스템 입력

**고정 입력 (배포 전 1회 학습)**
- 전문가 피드백 데이터: `data/feedback_extractor.py` → `feedback_db.jsonl` → `data/few_shot_builder.py` → 매니저 가중치 컨텍스트 생성 (`manager_weight_context.json`)
- RAG 검색기: 제거됨 — 연구 설계 공정성 문제로 파이프라인에서 제거
- 루브릭: 각 하위 에이전트 시스템 프롬프트에 해당 영역 루브릭 직접 내장

**매 호출 입력**
- 학생 에세이 전문 (AI Hub `essay_answer.text`)
- 과제 지시문 (AI Hub `essay_question.prompt`)
- 학생 학년 (예: "중1")

## 2. 오케스트레이션 구조

### 2.1 Python 하드코딩 오케스트레이션

ADK LlmAgent 기반 매니저 에이전트를 사용하지 않고 Python이 각 단계를 직접 순서대로 호출한다.  
배경: ADK LlmAgent가 도구 호출 후 텍스트를 생성하지 않는 빈 응답 문제의 구조적 해결.

```
STEP 1: _llm(DIAGNOSIS_PROMPT)                    ← LLM 단독 호출: 취약 신호 진단 + 가중치 산출
STEP 2: _run_adk_agent(parallel_feedback)          ← ADK ParallelAgent: 4개 에이전트 동시 실행
STEP 3: _llm(SYNTHESIS_PROMPT)                    ← LLM 단독 호출: 종합 피드백 초안 생성
STEP 4: 검증 루프 (검증 최대 3회 / refine 최대 2회)
        _run_adk_agent(verification_agent)          ← ADK LlmAgent: MISCA 기반 검증
        미충족 트리거(C1·C2·M1·M4) 있으면:
          _llm(REFINE_MANAGER_PROMPT)               ← LLM 매니저: 검증 결과 분석 → 재실행 에이전트 선택
          _run_adk_agent(selected_sub_agents)       ← 선택된 하위 에이전트만 재실행
          _llm(SYNTHESIS_PATCH_PROMPT)              ← 재실행 결과로 해당 영역만 교체
```

**파이프라인 분리 API** (`pipeline.py`):
- `run_mafs_synthesis()` → Steps 1-3 결과를 `SynthesisResult` dataclass로 반환
- `run_mafs_verify(sr)` → Step 4(검증 루프)만 실행
- `run_mafs()` → 두 함수를 순서대로 호출하는 편의 래퍼

RQ1·RQ2 평가에서 `run_mafs_synthesis()`로 synthesis_0를 생성한 뒤, B조건(검증 없음)에는 synthesis_0를 그대로 사용하고 A조건(검증 포함)에는 동일한 sr에 `run_mafs_verify()`를 적용한다. 두 조건이 동일한 synthesis_0를 공유하므로 stochastic 변동에 의한 A<B 역전이 원천 차단된다.

### 2.2 에이전트 구조

| 에이전트 | 유형 | 역할 요약 |
|----------|------|-----------|
| 진단·합성 (LLM 직접 호출) | Python `_llm()` | 취약 신호 진단 + 가중치 산출 / 4개 결과 통합 → 종합 피드백 |
| 과제수행 에이전트 | ADK LlmAgent (Parallel) | 과제 지시문의 독자·목적·조건 충족 여부 판단 → 피드백 초안 생성 |
| 내용 에이전트 | ADK LlmAgent (Parallel) | 명료성·구체성·적절성 판단 → 피드백 초안 생성 |
| 조직 에이전트 | ADK LlmAgent (Parallel) | 연결성·통일성 판단 → 피드백 초안 생성 |
| 표현 에이전트 | ADK LlmAgent (Parallel) | 어휘 적절성·어법 정확성 판단 → 피드백 초안 생성 |
| 검증 에이전트 | ADK LlmAgent | MISCA 기반 C1~C5·M1·M3~M5 기준(9개, M2 분석 타당성은 사후 독립 판사 전용)으로 피드백 초안 질적 검토 → 재합성 트리거 또는 종료 |

※ 4개 병렬 에이전트는 점수를 산출하지 않고 피드백 초안만 생성한다.  
※ 4개 병렬 에이전트는 진단·가중치 결과를 받지 않는다 — 각 영역을 독립적으로 상세 분석한다.  
※ 검증 에이전트는 진단 결과(가중치·취약 신호)를 수신하지 않는다 (확증 편향 방지).

### 2.3 검증 루프 상세

```
verify_1 → refine_1 → verify_2 → refine_2 → verify_3 → 종료
```

- 트리거 기준(C1·C2·M1·M4) 모두 충족 → 즉시 종료
- verify_2 와 verify_3에서 동일 기준 연속 미충족 → 재실행 없이 종료 (효과 없다고 판단)
- verify_3 도달 시 → 재실행 없이 종료

#### refine 단계 상세 (LLM 기반 매니저 라우팅)

Python 하드코딩으로 "C1 미충족이면 parallel_feedback 재실행" 같이 분기하지 않는다. 대신 REFINE_MANAGER_PROMPT를 사용해 LLM 매니저가 검증 결과를 읽고 스스로 판단한다.

```
refine_n:
  1. _llm(REFINE_MANAGER_PROMPT, [검증 결과 + 현재 합성 + 에세이 + 과제 지시문])
     → 출력: "재실행: task_agent, content_agent"
             "task_agent: [재실행 지시]"
             "content_agent: [재실행 지시]"
  2. _parse_refine_decision() → {에이전트명: 지시문} dict
  3. 선택된 에이전트만 재실행 (재실행 지시 포함 입력)
  4. _llm(SYNTHESIS_PATCH_PROMPT, [기존 합성 + 새 에이전트 출력 + 에세이 + 과제 지시문])
     → 해당 영역만 교체, 나머지 영역 그대로 유지
```

REFINE_MANAGER_PROMPT 제약: 반드시 최소 1개 이상의 에이전트 선택. "없음" 허용 안 됨.
파싱 실패 fallback: task_agent 기본 실행 (M1·M4 실패의 가장 흔한 담당자).

### 2.4 Context Engineering 설계 원칙

Context engineering은 LLM에 전달되는 컨텍스트 창(context window)의 내용을 체계적으로 설계하여 모델의 추론 품질을 최적화하는 방법론이다(Karpathy, 2025). MAFS에서는 다음 다섯 가지 원칙으로 구체화된다.

---

#### 원칙 1. 단계적 컨텍스트 누적 (Progressive Context Accumulation)

각 단계는 이전 단계 출력을 선택적으로 다음 단계 컨텍스트에 포함한다. 모든 이전 정보를 무조건 누적하지 않고, 해당 단계의 역할 수행에 필요한 정보만 포함함으로써 컨텍스트 오염과 불필요한 토큰 소모를 방지한다.

| 단계 | 컨텍스트 구성 |
|------|--------------|
| STEP 1 진단 | 에세이 + 과제 지시문 + 학년 + **도메인 지식(전문가 가중치)** |
| STEP 2 서브에이전트 | 에세이 + 과제 지시문 + 학년 *(진단 결과 제외)* |
| STEP 3 합성 | 에세이 + 과제 지시문 + 학년 + **진단 결과** + **서브에이전트 분석** |
| STEP 4 검증 | **피드백 초안** + 에세이 + 과제 지시문 *(진단·합성 과정 제외)* |
| REFINE 매니저 | **검증 결과** + **현재 합성** + 에세이 + 과제 지시문 |
| REFINE 서브에이전트 | 에세이 + 과제 지시문 + 학년 + **재실행 지시** |
| SYNTHESIS PATCH | **기존 합성** + **재실행 에이전트 새 분석** + 에세이 + 과제 지시문 |

---

#### 원칙 2. 컨텍스트 격리를 통한 편향 차단 (Context Isolation)

에이전트 간 정보 공유를 의도적으로 제한하여 두 가지 편향을 차단한다.

**① 확증 편향 차단 — 검증 에이전트**

검증 에이전트는 매니저의 진단 결과(가중치·취약도 판단)를 수신하지 않는다. 매니저가 "조직 영역이 HIGH"라고 판단했더라도 검증 에이전트는 그 판단을 모른 채 피드백 텍스트만 독립적으로 평가한다. 매니저 추론을 알면 그 결론에 동조하는 방향으로 채점이 기울 수 있기 때문이다.

**② 상호 간섭 차단 — 4개 병렬 에이전트**

과제수행·내용·조직·표현 에이전트는 서로의 출력을 보지 않으며 진단 가중치도 수신하지 않는다. 각 에이전트가 자신의 루브릭 기준으로 에세이를 독립 분석하므로, 다른 에이전트의 판단이나 매니저의 우선순위가 분석 내용에 영향을 미치지 않는다.

---

#### 원칙 3. 도메인 지식 주입 (Domain Knowledge Injection)

진단 단계의 컨텍스트에 AI Hub 전문가 피드백 데이터에서 학습된 가중치 분포를 주입한다.

```
[전문가 피드백 가중치 참고 데이터]  ← manager_weight_context.json
{DIAGNOSIS_PROMPT 본문}
```

이 참고 데이터는 목적별(설명문·설득문·친교및정서)·취약도별(HIGH/MEDIUM/LOW) 전문가 평균 가중치 분포를 담고 있으며, N=16,010건의 전문가 피드백에서 추출하였다. LLM은 이 분포를 맹목적으로 따르지 않고 에세이를 직접 읽은 자신의 판단과 결합하여 최종 가중치를 결정한다.

---

#### 원칙 4. 동적 컨텍스트 확장 (Dynamic Context Enrichment)

입력 상황에 따라 컨텍스트를 동적으로 보강한다.

**① 글쓰기 목적 힌트**

AI Hub 메타데이터에 목적 정보가 있으면 `[글쓰기 목적 힌트]` 섹션을 base_input에 추가한다. DIAGNOSIS 에이전트가 과제 지시문만으로 목적을 오판하는 경우를 방지한다.

```
[글쓰기]  ...
[과제 지시문]  ...
[학생 학년]  ...
[글쓰기 목적 힌트]  설명문          ← 메타데이터 있을 때만 추가
```

**② 재실행 지시 (Refine Instruction)**

미충족 트리거가 있을 경우 REFINE_MANAGER_PROMPT가 에이전트별 구체적 재실행 지시를 생성하고, 이를 해당 에이전트 재실행 시 컨텍스트에 추가한다. 에이전트가 이전과 동일한 입력으로 반복 실행되는 것이 아니라, 무엇을 개선해야 하는지 명시된 지시를 받고 실행된다.

---

#### 원칙 5. 구조화 입력 포맷 (Structured Context Formatting)

모든 컨텍스트는 대괄호 레이블(`[섹션명]`)로 명시적으로 구분한다. LLM이 각 섹션의 역할을 혼동 없이 파악하도록 하기 위함이다.

```
[피드백 초안]     ← 검증·재합성 단계에서 평가 대상
[에세이]          ← 학생 원문
[과제 지시문]     ← 과제 조건 참조 기준
[가중치 진단]     ← 합성 단계에서 분량 배분 기준
[영역별 분석 결과] ← 합성 단계에서 내용 소스
[재실행 지시]     ← refine 단계에서 에이전트별 개선 요구사항
[재실행 에이전트 새 분석] ← patch 단계에서 교체할 영역 소스
```

## 3. 에이전트별 상세 설계

### 3.1 진단 단계 (DIAGNOSIS_PROMPT)

#### 3.1.1 역할
- 학생 에세이 전체를 읽고 영역별 취약 신호를 LLM 단독으로 판단
- 전문가 피드백 데이터 학습 결과(목적별·취약 패턴별 평균 분포)를 참고하여 최종 가중치 산출
- 출력: 영역별 우선순위(HIGH/MEDIUM/LOW)와 최종 가중치 (내부 계산용, 최종 피드백에는 노출하지 않음)

#### 3.1.2 가중치 산출 방식
1. 에세이의 글쓰기 목적(설명/설득/친교 및 정서)을 판단
2. 주입된 전문가 학습 데이터에서 해당 목적의 "목적별 평균" 행을 기본값으로 사용
3. 취약 영역이 있으면 해당 영역의 "취약 (N=...)" 행 수치 방향으로 조정
4. 4개 영역 가중치 합계 1.0으로 정규화

※ 학습 데이터 없을 때 fallback: 에세이 직접 읽고 LLM이 독자적으로 판단

#### 3.1.3 영역별 내용 취약 신호 기준 (목적 구분)
- 설명문: 설명 대상 특성 다양성(정의·기능·종류·사례·비교·장점·단점), 구체성
- 설득문: 주장 명확성, 근거 충분성, 반론 고려
- 감상문: 경험 구체성, 정서 연결, 독자 공감

#### 3.1.4 입력 컨텍스트
- 학생 에세이 전문
- 과제 지시문
- 학생 학년
- [프롬프트 앞에 주입] 전문가 피드백 학습 결과: 전체·목적별·취약도별 평균 가중치 (초5~중3 국어·사회·과학 전체)

---

### 3.2 합성 단계 (SYNTHESIS_PROMPT)

#### 3.2.1 역할
- 진단 단계 가중치 + 4개 병렬 에이전트 결과를 입력받아 종합 피드백 초안 생성 (SYNTHESIS_PROMPT)
- refine 시: SYNTHESIS_PATCH_PROMPT가 기존 합성 + 재실행 에이전트 새 분석을 받아 해당 영역만 교체. 전체 재합성 아님.

#### 3.2.2 RAG 전문가 피드백 참조 (제거됨)

RAG는 연구 설계 공정성 문제로 파이프라인에서 제거되었다. MAFS는 Training 전문가 피드백을 참조하고 Baseline은 참조하지 않아 비교 조건이 불균형해지기 때문이다. 취약 영역 집중 피드백은 RAG가 아닌 DIAGNOSIS 단계의 동적 가중치가 담당하므로 기능 손실은 없다.

#### 3.2.3 도구 분석 수치 보존 원칙
4개 병렬 에이전트가 도구를 통해 산출한 수치와 직접 인용은 최종 피드백에도 반드시 보존한다.

| 도구 출력 | 보존 방식 |
|-----------|----------|
| 맞춤법 오류 건수 | "맞춤법 오류 3건" → "맞춤법 오류가 세 군데 발견됐습니다" |
| 특성/근거/정서표현 개수 | "특성 개수: 2개" → "설명 대상의 특성을 두 가지 다루고 있습니다" |
| 접속어 유형·빈도 | "인과 0건, 순접 4건" → 자연스러운 문장으로 변환하되 수치 포함 |
| 에세이 직접 인용 | 따옴표 안의 인용 텍스트는 최종 피드백에도 구체적으로 포함 |

수치와 직접 인용이 사라지면 LLM이 추론한 것과 구별되지 않는 피드백이 된다.

#### 3.2.4 분량 배분 원칙
- 최종 가중치 X%인 영역은 전체 피드백의 약 X% 분량 할당
- 영역당 문단 하나 (4개 문단 구조)

#### 3.2.5 목적별 피드백 톤
- 설명문: 분석적·객관적 ("독자 입장에서 이해하기 쉬운지")
- 설득문: 논리적·비판적 ("읽는 사람을 납득시킬 수 있는지")
- 감상문: 공감적·따뜻한 ("읽는 사람이 상황을 함께 느낄 수 있는지")

#### 3.2.6 학년별 문체
- 초1~3: 짧은 문장, 쉬운 어휘
- 초4~6: 간결한 설명 중심
- 중1~3: 중학교 수준 어휘, 논리적 문체
- 고1~3: 고등학교 수준 어휘, 분석적 문체

#### 3.2.7 입력 컨텍스트
- 학생 에세이 전문 + 과제 지시문 + 학생 학년
- 진단 단계 가중치 결과
- 4개 병렬 에이전트 피드백 초안 전체
- [재합성 시 추가] 검증 에이전트 지적 사항 전문 (미충족 기준별 판단 근거 포함)

---

### 3.3 과제수행 에이전트 (Task Completion Agent)

과제 지시문에 명시된 독자·목적·조건을 학생이 얼마나 충족했는지 판단하고 피드백 초안을 생성한다.

※ **조건의 의미**: AI Hub 과제 지시문(`essay_question.prompt`)에 담긴 요구사항. 예) "중학생 독자를 대상으로, 긍정적·부정적 측면을 모두 포함하여 쓰시오" → 독자(중학생), 내용 조건(양면 포함), 목적(설명).

#### 3.3.1 LLM 역할
- 에세이가 과제의 독자·목적·조건을 얼마나 반영했는지 판단
- 조건 충족 정도를 기반으로 피드백 방향과 깊이 결정
- 근거 문장 추출 도구 결과를 바탕으로 과제수행 피드백 초안 작성

#### 3.3.2 규칙 기반 자율성 — 조건 충족 정도에 따른 분기
- 조건을 아예 무시한 경우 → 핵심 조건이 무엇인지부터 설명하는 피드백 생성
- 조건을 부분 반영한 경우 → 반영된 부분은 인정하고 미충족 조건에만 집중하여 지적
- 조건을 대부분 충족한 경우 → 미충족된 세부 조건만 간략히 피드백

#### 3.3.3 학년별 기준 조정
- 초5~6: 지시문 조건이 1~2개인 경우 핵심 조건만 충족해도 "우수". 분량 조건은 10% 미만 미달이면 무시.
- 중1~3: 복합 조건(형식+내용+소재+분량)을 모두 개별 확인. 기본 루브릭 그대로 적용.

#### 3.3.4 사용 도구
- 근거 문장 추출 Function Tool: 과제 조건 이행·미이행의 증거가 되는 에세이 문장 위치 특정

#### 3.3.5 입력 컨텍스트
- 학생 에세이 전문 + 과제 지시문
- [시스템 프롬프트] 과제수행 루브릭 (zero-shot — few-shot 제거됨)

---

### 3.4 내용 에이전트 (Content Agent)

명료성(초점화 여부)·구체성(세부 내용 충분 여부)·적절성(설명 대상 특성 개수)을 판단하고 피드백 초안을 생성한다.

#### 3.4.1 LLM 역할
- 에세이의 글쓰기 목적을 먼저 파악 (설명/설득/감상에 따라 판단 기준 적용)
- 설명문: 설명 대상 특성 후보 추출 → 카운팅 Function Tool에 전달 (적절성)
- 설득문: 주장·근거·반론 명확성 판단
- 감상문: 경험 구체성·정서 연결 판단
- 특성 개수 + 근거 문장을 종합하여 내용 피드백 초안 작성

#### 3.4.2 규칙 기반 자율성 — 목적별 분기
- 설명문 + 특성 개수 ≥ 기준치(3개) → 적절성 피드백 생략, 명료성·구체성에만 집중
- 설명문 + 특성 개수 부족 → 어떤 특성이 더 필요한지 구체적 예시와 함께 적절성 피드백 생성
- 설득문 + 근거 부족 → 어떤 근거가 추가로 필요한지 제안

#### 3.4.3 학년별 기준 조정
- 초5~6: 특성/근거/정서표현 개수 기준 1단계 완화 적용 (예: 특성 3개 → 우수, 2개 → 보통). 일상 경험·단순 사례로도 구체성 인정.
- 중1~3: 기본 루브릭 기준 그대로 적용. 수치·비교·통계 등 더 엄격한 근거 기대.

#### 3.4.4 사용 도구
- 근거 문장 추출 Function Tool: 명료성·구체성 부족의 증거가 되는 에세이 문장 위치 특정
- 특성 카운팅 Function Tool: LLM이 특성 후보 추출 → 도구가 개수 산출 (설명문에서만 활용)

#### 3.4.5 입력 컨텍스트
- 학생 에세이 전문 + 과제 지시문
- [시스템 프롬프트] 내용 루브릭 3개 항목 (명료성·구체성·적절성) (zero-shot — few-shot 제거됨)

---

### 3.5 조직 에이전트 (Organization Agent)

문장·문단 간 연결 자연스러움(연결성)과 주제 이탈 여부(통일성)를 판단하고 피드백 초안을 생성한다.

#### 3.5.1 LLM 역할
- 접속어 분석 도구의 빈도·다양성 수치를 참고하여 연결성 수준 판단
- 두 문장의 관계(순접·역접·인과 등)를 읽고 접속어 적절성 판단
- 문단 구조와 주제 흐름을 읽고 통일성 이탈 여부 판단 (의미적 이탈 판단은 LLM이 적합)
- 근거 문장 + 분석 결과를 종합하여 조직 피드백 초안 작성

#### 3.5.2 규칙 기반 자율성 — 접속어 분석 결과 기반 분기
- 접속어가 다양하고 충분 → 연결성 피드백 생략, 통일성에 집중
- 특정 유형 접속어만 반복 → 필요한 구간에만 다양한 접속어 사용 제안
- 접속어 없이도 문장 관계가 자연스러운 구간 → 접속어 추천 안 함
- 주제 이탈 문장 발견 → 해당 문장을 근거로 통일성 피드백 집중 생성

#### 3.5.3 학년별 기준 조정
- 초5~6: 접속어 2가지 유형 이상이면 "우수"로 판단. "그리고"/"그래서" 70% 이상일 때만 편중으로 판단.
- 중1~3: 3가지 유형 이상이어야 "우수". "그리고"/"그래서" 60% 이상이면 편중 판단.

#### 3.5.4 사용 도구
- 접속어·연결어 분석 Function Tool (Python): 한국어 접속어 목록 딕셔너리 매칭 → 유형별(순접·역접·인과·예시·전환·양보) 빈도·다양성 수치 산출
- 근거 문장 추출 Function Tool: 연결이 어색한 구간·주제 이탈 문장 위치 특정

#### 3.5.5 입력 컨텍스트
- 학생 에세이 전문
- [시스템 프롬프트] 조직 루브릭 2개 항목 (연결성·통일성) (zero-shot — few-shot 제거됨)

---

### 3.6 표현 에이전트 (Expression Agent)

어휘 선택 적절성과 맞춤법·띄어쓰기 정확도를 판단하고 피드백 초안을 생성한다.

#### 3.6.1 LLM 역할
- 어휘 선택이 문맥에 적절한지, 문장이 자연스러운지 판단 (어휘 영역 — LLM 담당)
- 맞춤법 API 오류 결과를 참고하여 어법 피드백 문장 생성 (어법 영역 — API 결과 기반)
- 두 영역 결과를 종합하여 표현 피드백 초안 작성

※ 맞춤법 API → 어법 / LLM → 어휘·문맥으로 역할 분리. LLM 단독으로 맞춤법·띄어쓰기 오류를 일관되게 탐지하면 hallucination 위험이 있어 API로 보완

#### 3.6.2 규칙 기반 자율성 — 맞춤법 API 결과 기반 분기
- 어법 오류 없음 → 어법 피드백 생략, 어휘 적절성에만 집중
- 오류 소수(1~2개) → 해당 문장 근거로 간략한 어법 피드백
- 오류 다수 → 오류 유형별로 구조화하여 어법 피드백 집중 생성, 어휘는 간략히

#### 3.6.3 학년별 기준 조정
- 초5~6: 오류 4개 이하면 "보통"으로 판단. 단순 띄어쓰기 오류는 비중 낮게 반영. 구어체 지적 시 대체 표현 1개만 제시.
- 중1~3: 기본 루브릭 기준 그대로 적용. 어휘 다양성과 문어체 수준 더 엄격하게 기대.

#### 3.6.4 사용 도구
- 맞춤법 검사 API (`check_spelling`, 직접 HTTP 호출): 부산대학교 인공지능연구실과 (주)나라인포테크의 한국어 맞춤법·문법 검사기를 활용한 오픈소스 API 서버(jhaemin/speller-api, https://github.com/jhaemin/speller-api , 배포 주소 https://speller.town )를 재시도 없이 1회 호출. 맞춤법·띄어쓰기 오류 탐지 → 어법 피드백의 객관적 근거. 호출 실패 시 예외를 포착해 `status: "error"`를 반환하며, 표현 에이전트 프롬프트에 이 경우 어법 피드백을 생략하고 어휘 적절성 판단에만 집중하도록 지침을 명시.
- 근거 문장 추출 Function Tool: 오류·어색 표현의 증거가 되는 에세이 문장 위치 특정

#### 3.6.5 입력 컨텍스트
- 학생 에세이 전문
- [시스템 프롬프트] 표현 루브릭 2개 항목 (어휘 적절성·어법 정확성) (zero-shot — few-shot 제거됨)

---

### 3.7 검증 에이전트 (Verification Agent)

MISCA 모형 전문가 관점에서 피드백 초안을 질적으로 검토하고, 재합성 트리거 기준 미충족 시 구체적 지적 사항을 반환한다.

※ **재합성 트리거의 의미**: 해당 기준이 미충족되면 합성 단계에 재작업 신호를 보내는 기준. 트리거 기준이 미충족이면 어떤 영역의 무엇이 문제인지 서술형으로 지적하고, Python 오케스트레이터가 SYNTHESIS_PROMPT를 재호출. 최대 2회 반복.

#### 3.7.1 LLM 역할
- 시스템 프롬프트 내장 기준(C1~C5·M1·M3~M5, 9개 — M2 분석 타당성은 사후 독립 판사 전용)으로 피드백 초안을 질적 판단
- 각 기준에 대해 "왜 충족/미충족인지"를 서술형으로 판단 (단순 체크가 아닌 질적 판단)
- 트리거 기준 미충족 시 어떤 영역 피드백이 문제인지 구체적 지적 사항 생성
- LLM Judge (Agent-as-a-Tool) 호출: MISCA 전문가 페르소나로 서술형 질적 판단

#### 3.7.2 규칙 기반 자율성 — 반복 미충족 감지
- 1차·2차 검증에서 같은 기준이 반복 미충족 → 재합성 효과 없다고 판단, 현재 상태로 종료
- 트리거 기준 모두 충족 → 즉시 종료 신호
- 출력 형식: 트리거 기준만 `✗`/`✓` 기호 사용 → Python 오케스트레이터가 키워드 감지 (`C1 ✗`, `C2 ✗`, `M1 ✗`, `M4 ✗`)

#### 3.7.3 사용 도구
- LLM Judge (Agent-as-a-Tool): MISCA 전문가 페르소나로 서술형 질적 판단 수행

#### 3.7.4 입력 컨텍스트
- 피드백 초안 (합성 단계 결과)
- 학생 에세이 전문 (C1 관련성 판단용)
- 과제 지시문 (M4 과제 맥락 판단용)
- [시스템 프롬프트] MISCA 모형 설명 전문 + C1~C5·M1·M3~M5 판단 기준 (강화된 임계값 포함)

※ 진단 결과(가중치·취약 신호)는 수신하지 않는다 — 확증 편향 방지

## 4. 검증 기준 상세 (C1~C5 + M1~M5)

### 4.1 기준 설계 원칙

C1~C5는 Jordan et al.(2025)의 MAGIC 논문에서 제시한 피드백 품질 기준이다. M2(분석 타당성)는 분석 타당성 확보를 위해 본 연구에서 추가한 기준이다. M1·M3~M5는 Panadero & Lipnevich(2022)의 MISCA 피드백 모형(Message, Implementation, Student, Context, Agents)에서 검증 단계에서 실제로 판단 가능한 요소만 추출하여 본 연구에서 설계한 추가 기준이다.

※ M1·M3~M5 설계 근거: MISCA의 Message 요소는 C1~C5에서 이미 커버됨. 나머지 요소 중 검증 에이전트가 피드백 초안을 보고 직접 판단 가능한 것만 M 항목으로 전환. Context와 Agents 요소는 시스템 설계 자체에서 이미 반영되어 있어 결과물 차원에서만 최소한으로 확인

#### 트리거 vs 참고 전달 구분 원칙

10개 기준은 **재합성 트리거**(미충족 시 합성 단계 재호출)와 **참고 전달**(미충족이어도 재합성 없이 정보로만 전달)로 구분된다. 아래 세 조건을 모두 충족하는 기준만 트리거로 지정한다.

| 조건 | 내용 |
|------|------|
| ① 교육적 최소 요건 | 미충족 시 피드백이 교육적 기능을 근본적으로 상실하는가? |
| ② 재합성 교정 가능성 | 합성 단계에 구체적 지적 사항을 주입하면 해당 기준을 충족시킬 수 있는가? |
| ③ 판단 신뢰성 | 검증 에이전트가 객관적 근거를 토대로 일관되게 판단할 수 있는가? |

세 조건 중 하나라도 해당하지 않으면 참고 전달로 분류한다.

### 4.2 C1~C5 피드백 품질 기준

| 기준 | 판단 질문 | MISCA 요소 | 분류 | 분류 근거 |
|------|-----------|------------|------|-----------|
| C1 | 피드백이 학생 에세이 내용과 직접 관련 있는가? | Message | **트리거** | ①미충족 시 어느 학생에게나 붙일 수 있는 일반론 피드백이 됨 — 교육적 가치 소멸. ②직접 인용·명시적 참조 지시로 교정 가능. ③따옴표 인용·명시적 참조 유무로 객관 판단 가능 |
| C2 | 학생 글의 약점을 구체적으로 짚었는가? | Message | **트리거** | ①약점이 막연하면 학생이 무엇을 고쳐야 하는지 알 수 없어 피드백의 개선 기능이 사라짐. ②(위치+이유) 두 가지 명시 지시로 교정 가능. ③위치·이유 각각의 존재 여부로 객관 판단 가능 |
| C3 | 학생 글의 강점도 언급했는가? | Message | **참고** | ②글에 진정한 강점이 없는 경우 억지 칭찬을 강요하게 되어 오히려 품질 저하 위험. 합성 단계에서 강점 유무는 글 내용에 달려 있어 재합성으로 교정하기 어려움 |
| C4 | 피드백이 도구 분석 수치나 학년 기준을 근거로 제시하는가? | Implementation | **참고** | ③"즉시 실행 가능한가"는 학년·과제 맥락에 따라 기준이 달라 LLM 판단 일관성이 낮았음(파일럿에서 Baseline이 MAFS보다 높게 나옴) → "분석 근거의 수치화" 여부로 재정의해 MAFS 고유 강점(도구 사용)을 측정하도록 변경 |
| C5 | 학생에게 전반적으로 도움이 되는가? | Student | **참고** | ③C1·C2·M1·M4가 모두 충족된 피드백이라면 도움이 된다는 결론은 종합적·주관적 판단이므로, 이 기준만 독립적으로 재합성을 트리거하면 불필요한 루프가 발생함 |

### 4.3 M1~M5 MISCA 기반 추가 기준 (M2는 본 연구 설계)

| 기준 | 판단 질문 | MISCA 요소 | 분류 | 분류 근거 |
|------|-----------|------------|------|-----------|
| M1 | 다음에 무엇을 개선할지 방향을 제시하는가? (feed forward) | Implementation | **트리거** | ①Hattie & Timperley(2007)의 "Where to next?" — feed forward가 없으면 피드백이 과거 평가로만 기능하며 학습 향상에 연결되지 않음. ②"다음에는 ~해 보세요" 형식의 명시적 지침 삽입 지시로 교정 가능. ③명시적 형식 유무로 객관 판단 가능 |
| M2 | 지적한 약점·강점이 에세이 실제 내용에 비추어 타당한가? | Message | **참고** | ②없는 내용 언급·좋은 부분을 약점으로 지적은 재합성보다 에이전트 설계(hallucination 방지 도구)로 예방하는 것이 우선 |
| M3 | 피드백 언어가 초5~중3 수준에 적절한가? | Student | **참고** | ②SYNTHESIS_PROMPT에 학년별 문체(초4~6 간결체 / 중1~3 논리체)가 이미 지정되어 있어 생성 단계에서 대부분 처리됨. 재합성으로 어휘 수준을 교정하면 내용이 함께 바뀌는 부작용 위험 |
| M4 | 피드백이 과제 맥락(목적·조건)을 반영하는가? | Context | **트리거** | ①과제 맥락 없는 피드백은 어느 과제에나 붙일 수 있는 일반론이 되어 해당 학생의 과제수행 상황과 연결되지 않음. ②과제 지시문의 구체 조건 인용 지시로 교정 가능. ③지시문 조건의 인용·참조 여부로 객관 판단 가능 |
| M5 | 4개 영역이 모두 다루어지고 분량이 균형 있는가? | Agents | **참고** | ②SYNTHESIS_PROMPT에 가중치 비례 분량 배분·영역당 문단 하나 원칙이 이미 설계되어 있어 구조적으로 대부분 충족됨. 미충족 시에도 재합성보다 설계 단계 점검이 우선 |

## 5. 전문가 피드백 데이터 학습 파이프라인

### 5.1 개요

배포 전 1회 실행. AI Hub 전문가 피드백 데이터에서 LLM이 참고할 컨텍스트를 추출하여 파일로 저장한다. 런타임에서는 저장된 파일을 로드하여 각 에이전트 시스템 프롬프트에 주입하거나 DIAGNOSIS_PROMPT 앞에 삽입한다.

**설계 원칙**: LLM이 에세이를 먼저 스스로 읽고 판단한 뒤, 전문가가 비슷한 글에 어떻게 피드백했는지를 참고한다. 단순 분량 비율이 아니라 전문가 피드백의 언어·관점·깊이까지 학습한다.

### 5.2 파이프라인 구성

```
AI Hub JSON (N=16,010)
    ↓ data/feedback_extractor.py
data/feedback_db.jsonl             ← 에세이 1개 = 1줄 (grade·purpose·essay·prompt·domains 포함)
    ├─ data/few_shot_builder.py
    │       ↓
    │  data/manager_weight_context.json  ← DIAGNOSIS_PROMPT 주입용: 전체·목적별·취약도별 평균 가중치
    └─ (tools/rag_retriever.py — 현재 미사용: 연구 설계 공정성 문제로 파이프라인에서 제거)
```

> **※ few-shot 예시 파일 제거됨**: 자동 선별 예시 품질 검토 결과 전부 최저점(score=1) 에세이에 대한
> 피드백이었고, M1 미충족 패턴("~해야 합니다" 등)을 포함하고 있어 제거 후 zero-shot으로 전환.

### 5.3 매니저 가중치 컨텍스트 (manager_weight_context.json)

- 전체 평균: 초5~중3 국어·사회·과학 전체 데이터 기반 (학년·과목·목적별 분포 포함)
- 목적별 평균: 설명문·설득문·친교 및 정서 각각의 영역별 가중치 분포
- 취약도별 평균: 특정 영역 점수가 낮을 때 전문가가 그 영역에 얼마나 집중했는지 (N≥10인 경우만 포함)
- 런타임 주입: `run_mafs()` 호출 시 `DIAGNOSIS_PROMPT` 앞에 문자열로 삽입

### 5.4 RAG 검색기 — 제거됨

연구 설계 공정성 문제로 파이프라인에서 제거되었다. MAFS는 Training 전문가 피드백을 참조하고 Baseline은 참조하지 않아 RQ1 비교 조건이 불균형해지기 때문이다. 취약 영역 집중 피드백은 DIAGNOSIS 단계 동적 가중치로 충분히 달성된다.

### 5.5 서브에이전트 학습 방식 — zero-shot

서브에이전트는 few-shot 예시 없이 시스템 프롬프트(루브릭·판단 기준·출력 형식)만으로 동작한다.

**few-shot 제거 이유**: 자동 선별 예시 품질 검토 결과
- 모든 예시가 avg_score=1(최저점) 에세이 — 중간·우수 글 피드백 패턴 학습 불가
- 전문가 피드백 텍스트 자체에 M1 미충족 패턴("~해야 합니다", "~필요합니다")이 다수 포함
- few-shot이 오히려 시스템 프롬프트에서 금지한 패턴을 강화시킬 위험 확인

**향후 재도입 조건**: 중간 이상 점수(avg_score ≥ 2.5) + MISCA 기준을 충족하는 예시를 수동 선별한 경우에 한해 재도입 가능

## 6. 도구 설계 요약

각 에이전트가 도구를 사용하는 이유는 LLM 단독으로는 불안정하거나 불일관한 작업을 보완하기 위해서다. **도구 출력 수치와 직접 인용은 합성 단계에서 최종 피드백에 보존**되어야 한다는 원칙을 전체 파이프라인이 공유한다.

| 도구 유형 | 사용 단계 | LLM 단독으로 안 되는 이유 |
|-----------|----------|--------------------------|
| 근거 문장 추출 Function Tool | 과제수행·내용·조직·표현 에이전트 | "어느 문장이 근거인지" LLM 출력이 불안정·hallucination 위험 → 에세이 문장 위치를 정확히 특정 필요 |
| 특성 추출 LLM → 카운팅 Function Tool | 내용 에이전트 | 루브릭이 특성 개수 기반 → LLM 단독 카운팅은 주관적·불일관 → 객관적 수치 확보 필요 |
| 접속어 분석 Function Tool (Python) | 조직 에이전트 | 접속어 빈도·다양성을 LLM이 수치로 일관되게 산출 불가 → Python 매칭으로 객관적 수치 확보 |
| 맞춤법 검사 API (`check_spelling`, 직접 HTTP) — jhaemin/speller-api (부산대 인공지능연구실·나라인포테크 엔진) | 표현 에이전트 | 맞춤법·띄어쓰기 오류를 LLM이 일관되게 탐지 못함 → API: 어법 / LLM: 어휘·문맥으로 역할 분리 |
| RAG 검색기 (제거됨) | — | 연구 설계 공정성 문제(MAFS만 Training 정답 예시 참조) |
| LLM Judge (Agent-as-a-Tool) | 검증 에이전트 | MISCA 전문가 페르소나로 서술형 질적 판단 수행 |

## 8. 연구 문제 및 평가 방법

### 8.1 연구 목적

본 연구는 LLM 기반 자동 피드백 시스템에서 **교육적 설계 요소**가 피드백 품질에 미치는 영향을 탐색하는 것을 목적으로 한다. 구체적으로, (1) 교육 이론에 기반한 상세 지침의 효과, (2) MISCA 기반 검증 루프의 기여, (3) 교과·목적·학년에 걸친 프롬프트 일반화 가능성을 각각 검토한다. 이를 통해 교육적 효과성 기준(MISCA 모형)에서 우수한 피드백을 생성하는 데 필요한 설계 조건을 밝힌다.

#### 표본 크기 결정 — G*Power 사전 검정력 분석

표본 크기는 G*Power 3.1을 사용한 사전 검정력 분석(a priori power analysis)으로 결정하였다.

**RQ1·RQ2 — 대응표본 t-검정**

| 항목 | 설정값 | 근거 |
|------|--------|------|
| Statistical test | Means: Difference between two dependent means (matched pairs) | 동일 에세이 쌍대 비교 |
| Tail(s) | Two | 방향성 사전 확정 불가 |
| Effect size d | 0.5 (중간 효과) | 파일럿 결과가 대효과였으나 본 실험에서 보수적으로 중간 효과 가정 |
| α err prob | 0.05 | 사회과학 관례 |
| Power (1-β) | 0.80 | 사회과학 관례 |

→ **필요 N = 34쌍**, 실제 검정력 = 0.8096

**RQ3 — Two-way ANOVA (5×2)**

| 항목 | 설정값 | 근거 |
|------|--------|------|
| Statistical test | ANOVA: Fixed effects, special, main effects and interactions | 5학년×2교과 요인설계 |
| Effect size f | 0.25 (중간 효과) | Cohen(1988) 교육학 연구 관례 |
| α err prob | 0.05 | — |
| Power (1-β) | 0.80 | — |
| Numerator df | 4 | 학년 주효과(5-1=4)로 가장 보수적인 효과 기준 |
| Number of groups | 10 | 5학년 × 2교과 = 10 셀 |

→ **최소 필요 N = 180** (셀당 18건), 실제 검정력 = 0.800  
→ 셀당 20건(총 200건) 선택 시 실제 검정력 ≈ **0.860**

### 8.4 평가 지표 (LLM 판사)

#### 판사 설계 원칙

피드백 품질은 독립적인 LLM 판사(`gemini-2.5-flash`, temperature=0)가 채점한다. 판사는 MAFS 파이프라인 내 검증 에이전트와 **완전히 별개의 독립 평가자**로 동작한다. 검증 에이전트가 생성 과정에서 재합성을 유발한 기준과 동일한 기준으로 최종 피드백을 사후 평가함으로써, MAFS 시스템의 내적 판단이 실제 품질 향상으로 이어지는지를 외부 시각에서 검증한다. LLM 평가자는 각 피드백이 어느 조건에서 생성되었는지 알 수 없도록, 조건 정보를 배제한 동일한 프롬프트로 채점하였다.

#### 판사 기준 임계값 설정 원칙

LLM 판사의 각 기준 충족 임계값은 **최소 지침(Baseline)과의 변별력 확보**를 기준으로 설정한다. 기준이 너무 낮으면 강력한 생성 모델이 어떤 지침에서도 충족시켜버려 조건 간 차이가 사라진다. 본 연구에서 RQ1 Baseline은 "다음 학생이 제출한 글에 대해 피드백을 작성해 주세요."로, 교육 이론·루브릭·구조화 지침이 전혀 없는 최소 지침이다. 이 조건이 유의미한 통제 조건이 되려면, 최소 지침만으로는 충족하기 어렵고 MAFS처럼 명시적으로 설계된 지침에서는 충족 가능한 수준으로 임계값을 조정해야 한다.

이에 따라 C1·C2·M4의 임계값을 강화하였다:
- C1: 참조 3→5개, 직접 인용 1→2개, 막연한 참조·오타 목록 나열 불인정
- C2: 지적 2→3건 + 에세이 직접 인용 추가 요건
- M4: 지시문 단순 나열이 아닌 에세이 내용과의 연결 분석 2가지 이상 요구

파일럿 실행(120건) 기준별 분포 분석 후 추가 기준 조정:
- C1: 직접 인용 2개 → **3개 이상**, 인용이 서로 다른 피드백 지점(강점·약점·feed forward)에 각각 연결되어야 함
- C3: 인용 1개 → **2개 이상** + 각 인용에 대해 "왜 강점인지" 설명 요구 (기존 기준에서 C3가 양쪽 모두 120건 전부 2점으로 변별력 0 확인)
- C4: "즉시 실행 가능성(how 행동 지침)" → **"분석 근거의 수치화"** 로 재정의. 맞춤법 오류 건수·접속어 유형 수·특성/근거 개수 등 도구 분석 수치 명시 또는 학년 기준 명시 여부 판단 (파일럿에서 Baseline이 MAFS보다 높게 나와 MAFS 고유 강점을 측정하는 기준으로 재설계)

---

#### 3점 루브릭 채점 방식 (0/1/2)

각 기준은 0=미충족 / 1=부분충족 / 2=완전충족 3단계로 채점한다.

이진 판정(0/1) 대신 3점 루브릭을 선택한 이유:
- MAFS와 Baseline이 기준을 "충족하는지 여부"는 같더라도, MAFS는 더 깊고 완전하게 충족함을 측정할 수 있다
- 1점(부분충족)이 두 조건 모두에 분포할 때, 2점(완전충족) 비율 차이가 핵심 발견이 된다
- 특히 M1(Feed Forward), C1(관련성), C4(분석 근거의 수치화)에서 부분충족(1점)과 완전충족(2점)의 구분이 중요하다

각 기준의 2점 조건:

| 기준 | 2점 (완전충족) 핵심 조건 |
|------|--------------------------|
| C1 | 학생 글의 특정 표현·문장·사례 **5개 이상** 참조, 그중 **3개 이상** 직접 인용, 각각 다른 피드백 항목에 연결 |
| C2 | 위치·이유·직접 인용을 갖춘 구체적 약점 지적 3건 이상 |
| C3 | 학생 글의 실제 표현·구조 **2개 이상** 직접 인용, 각각 강점인 이유 설명 |
| C4 | 도구 분석 수치(맞춤법 오류 건수·접속어 유형 수 등) 1개 이상 명시, 학년 수준에 비춘 기준 제시 |
| C5 | 약점 지적에 그치지 않고 개선 가능성과 동기를 함께 제시 |
| M1 | 학생 글의 특정 약점과 연결된 개선 지침을 "다음에는 ~해 보세요" 형식으로 명시 |
| M2 | 지적한 약점·강점이 학생 글에 비추어 모두 타당, 오분석·허위 언급 없음 |
| M3 | 어휘·문장·어조가 해당 학년 학생이 이해·수용 가능한 수준 |
| M4 | 과제 지시문 조건을 학생 글의 내용과 연결하여 2가지 이상 분석 |
| M5 | 과제 수행·내용·조직·표현 4개 영역 각각에 대해 학생 글의 근거를 포함한 분석 2문장 이상 |

#### 평가 기준 10개 — 선택 근거

기준은 두 선행 연구를 교육 맥락에 맞게 운영화한 것이다.

- **C1~C5**: MAGIC 논문(Jordan et al., 2025) — 논술형 글쓰기 피드백의 내용·실행 가능성 기준
- **M1~M5**: MISCA 모형(Panadero & Lipnevich, 2022) — 교육 피드백의 메시지·실행·학습자·맥락·행위자 요소. M2(분석 타당성)는 본 연구에서 MISCA 실행(Implementation) 요소로 조작화하여 추가

<표 4> LLM 평가자 채점 기준

| 기준 | 명칭 | 이론적 근거 | 완전 충족(2점) 핵심 조건 |
|------|------|------------|-------------------------|
| **C1\*** | 글쓰기 관련성 | MAGIC(내용 관련성) | 학생 글의 특정 표현·문장·사례 5개 이상 참조, 그중 3개 이상 직접 인용, 각각 다른 피드백 항목에 연결 |
| **C2\*** | 약점 구체성 | MAGIC(약점 강조) | 위치·이유·직접 인용을 갖춘 구체적 약점 지적 3건 이상 |
| **C3** | 강점 근거 | MAGIC(강점 강조) | 학생 글의 실제 표현·구조 2개 이상 직접 인용, 각각 강점인 이유 설명 |

| **C5** | 학습 성장 전제 | MAGIC(유용성) | 약점 지적에 그치지 않고 개선 가능성과 동기를 함께 제시 |

#### 트리거 기준 vs 참고 기준 — 평가 지표 구분

10개 기준은 MAFS 내 검증 루프에서의 역할에 따라 두 그룹으로 나뉜다.

**트리거 기준 (C1·C2·M1·M4)** — `score_trigger` (0~8)

| 기준 | 트리거 지정 이유 |
|------|----------------|
| C1 | 미충족 시 어느 학생에게나 붙일 수 있는 일반론이 되어 교육적 가치가 소멸됨 |
| C2 | 막연한 약점 지적은 학생이 무엇을 고쳐야 하는지 알 수 없어 피드백의 개선 기능이 사라짐 |
| M1 | Feed forward 없이는 피드백이 과거 평가로만 기능하며 학습 향상으로 연결되지 않음 (Hattie & Timperley, 2007) |
| M4 | 과제 맥락 없는 피드백은 해당 학생의 과제수행 상황과 연결되지 않는 일반론이 됨 |

**참고 기준 (C3·C4·C5·M2·M3·M5)** — `score_ref` (0~12)

| 기준 | 참고 전달인 이유 |
|------|----------------|
| C3 | 진정한 강점이 없는 글에서 억지 칭찬을 강요하면 품질 저하. 재합성으로 교정하기 어려움 |
| C4 | 도구 분석 수치·학년 기준 명시는 서술 스타일의 문제라 재합성 지시만으로 일관되게 교정하기 어려움. LLM 판사가 사후에 수치 인용 여부로 판별 |
| C5 | C1·C2·M1·M4 충족 피드백의 종합적·주관적 판단. 독립 트리거로 쓰면 불필요한 루프 발생 |
| M2 | 재합성보다 에이전트 설계(hallucination 방지 도구)로 예방하는 것이 우선 |
| M3 | 합성 프롬프트에 학년별 문체가 이미 설계되어 생성 단계에서 대부분 처리됨 |
| M5 | 합성 프롬프트에 가중치 비례 분량 배분·영역당 문단 하나 원칙이 설계되어 구조적으로 대부분 충족됨 |

---

#### 집계 지표

| 지표명 | 구성 기준 | 범위 | 주요 사용 RQ |
|--------|-----------|------|-------------|
| `score_total` | C1~C5 + M1~M5 전체 (기준당 0~2) | 0~20 | RQ1·RQ3 — 전반적 교육 품질 비교 |
| `score_trigger` | C1·C2·M1·M4 (기준당 0~2) | 0~8 | **RQ2 핵심** — 검증 루프가 직접 개선하는 기준 |
| `score_ref` | C3·C4·C5·M2·M3·M5 (기준당 0~2) | 0~12 | RQ2 보조 — 검증 루프의 간접 효과 확인 |

**score_trigger / score_ref 구분 근거**

LLM 판사는 10개 기준을 독립적으로 채점한다. 연구자가 이를 두 그룹으로 집계하는 이유는 **검증 루프의 효과 특이성(specificity)**을 검증하기 위해서다.

검증 루프는 트리거 기준(C1·C2·M1·M4) 미충족 시에만 재합성을 유발하도록 설계되어 있다. 따라서:

- **score_trigger**: 검증 루프가 직접 개입하는 기준의 합산 → RQ2의 핵심 지표. 검증 루프가 설계대로 작동한다면 이 점수에서 유의한 차이가 나와야 한다.
- **score_ref**: 검증 루프가 개입하지 않는 기준의 합산 → 특이성 검증용. score_trigger만 개선되고 score_ref에 차이가 없다면, 검증 루프가 의도한 기준만 선택적으로 개선함을 보여준다. 반대로 score_ref도 함께 개선된다면 합성 단계 자체의 전반적 품질 향상으로 해석된다.

이 구분은 처치 효과의 특이성을 확인하는 표준적 방법론(convergent-discriminant validation)에 해당한다.

---

#### 방법론적 한계 및 보완

**측정 기준 오염(criterion contamination) 문제**

MAFS 검증 에이전트는 MISCA 기준을 충족시키도록 피드백을 교정한다. LLM 판사가 동일한 MISCA 기준으로 최종 피드백을 평가하면, MAFS가 "시험 문제를 미리 알고 시험을 보는" 구조가 된다. 특히 RQ2에서 검증 루프가 MISCA 기준 점수를 높이는 결과는 **설계상 당연히 나올 수 있어** 외적 타당도가 약하다.

**이 설계가 그럼에도 유효한 근거**

1. LLM 판사는 MAFS 내부 상태(검증 에이전트의 판단·재합성 이력)에 접근하지 않고 최종 출력 텍스트만 독립적으로 평가한다
2. RQ1의 Baseline 조건이 외부 통제 역할을 한다 — Baseline이 MISCA 기준을 이유 없이 높게 달성하면 기준 자체의 변별력이 의심되지만, 그렇지 않다면 기준이 유의미한 차이를 포착하고 있다는 방어 근거가 된다
3. 교육적 피드백 연구에서 시스템의 목표 기준으로 효과를 측정하는 방식은 통용된다 (예: 수학 교육 앱을 수학 점수로 평가)

### 8.5 통계 분석 방법

분석 소프트웨어: **Jamovi**. N=200으로 중심극한정리(CLT)가 적용되어 합산 점수(0~20)의 정규 분포 가정이 충분히 성립하므로 모수 검정을 사용한다.

#### RQ1·RQ2 — 쌍대 비교 (동일 에세이, n=200쌍)

| 항목 | 내용 |
|------|------|
| 검정 | 대응표본 t-검정 (paired t-test) |
| 효과 크기 | Cohen's d |
| 해석 기준 | d ≥ 0.2: 소, d ≥ 0.5: 중, d ≥ 0.8: 대 |
| 유의 수준 | α = 0.05 (양측) |

#### RQ3 — 교과×학년 집단 비교 (5×2 균형 설계, n=200)

**ANOVA A — score_total (LLM 판사 점수 일관성)**

| 항목 | 내용 |
|------|------|
| 검정 | Two-way ANOVA (5학년 × 2교과) |
| 주효과 | 학년(5수준: 초5·초6·중1·중2·중3), 교과(2수준: 국어·사회) |
| 상호작용 | 학년 × 교과 |
| 효과 크기 | partial η² |
| 사후 검정 | Tukey HSD (학년 주효과 유의 시) |
| 유의 수준 | α = 0.05 |

**ANOVA B — gap_y (전문가 대비 타당도 검증)**

| 항목 | 내용 |
|------|------|
| 종속변수 | gap_y = expert_norm − llm_norm (0~1 정규화 후 차이) |
| 검정 | Two-way ANOVA (5학년 × 2교과) |
| 해석 방향 | 주효과·상호작용 모두 비유의 → LLM 판사가 전문가 기준 대비 학년·교과에 걸쳐 일관되게 작동 |

**RQ2 해석 지침**

#### STEP 4. RQ3 — Two-way ANOVA (Jamovi)

**분석 목적**: MAFS LLM 판사의 점수가 학년·교과에 걸쳐 일관되게 작동하는가를 두 방향으로 검증한다.  
- **ANOVA A (score_total)**: LLM 판사 점수 자체의 집단 간 차이  
- **ANOVA B (gap_y)**: Y = 전문가_정규화 − LLM판사_정규화의 집단 간 차이 → gap이 학년·교과 간 차이 없음이 타당도 증거

---

##### ANOVA A — score_total로 집단 비교

**Analyses → ANOVA → ANOVA**

1. Dependent Variable: `score_total`
2. Fixed Factors: `grade`, `subject`
3. Model: grade + subject + grade×subject (상호작용항 포함)
4. Effect Size: **η²p (partial eta-squared)** 체크
5. Post Hoc: `grade` 선택 → **Tukey** (학년 주효과 유의 시)
   - 출력에서 각 쌍(초5 vs 초6, 초5 vs 중1 등)의 평균 차이·p값 확인
   - 국어 vs 사회 비교는 교과 주효과 p값 하나로 충분
6. 상호작용 유의 시: **Estimated Marginal Means** → Plot 탭에서 grade(X축)·subject(선 구분) interaction plot 요청

**ANOVA A 결과 (score_total, N=200):**
> 학년의 주효과: F(4, 190) = 0.943, p = .440, η²p = .019 (비유의)  
> 교과의 주효과: F(1, 190) = 0.308, p = .579, η²p = .002 (비유의)  
> 학년×교과 상호작용: F(4, 190) = 1.371, p = .245, η²p = .028 (비유의)

모든 효과가 비유의이며 η²p 모두 소효과 미만. Tukey 사후검정: 모든 학년 쌍 p > .27, 국어·사회 p = .579. interaction plot에서 두 선이 18.8~20.0 범위 내에서 평행하게 유지됨.

---

##### ANOVA B — gap_y로 타당도 검증

**Analyses → ANOVA → ANOVA** (새 분석, rq3_spss.csv 동일 파일)

1. Dependent Variable: **`gap_y`** (Y = expert_norm − llm_norm)
2. Fixed Factors: `grade`, `subject`
3. Model: grade + subject + grade×subject
4. Effect Size: η²p 체크
5. Post Hoc: `grade` → Tukey (유의 시)
6. 기술통계: **Analyses → Exploration → Descriptives**  
   - 변수: `gap_y`, Split by: `grade`, `subject`  
   - 출력: 각 학년별·교과별 gap_y의 M, SD 확인  
   - 양수면 전문가 > LLM, 음수면 LLM > 전문가, 0에 가까우면 정렬됨

**ANOVA B 결과 (gap_y, N=200):**
> 학년 주효과: F(4, 190) = 1.731, p = .145, η²p = .035 (비유의)  
> 교과 주효과: F(1, 190) = 0.277, p = .599, η²p = .001 (비유의)  
> 학년×교과 상호작용: F(4, 190) = 2.903, p = .023, η²p = .058 (유의, 소효과)

주효과 모두 비유의. 상호작용이 유의하나 η²p = .058로 소효과 수준이며, score_total ANOVA에서는 동일 상호작용이 비유의(p = .245). 이는 LLM 판사 절대 점수의 일관성은 유지되며, 상호작용은 LLM 편향보다 전문가 평정자의 맥락별 기준 차이를 반영할 가능성이 있음을 시사한다. gap_y는 전 조건에서 음수(−0.30 ~ −0.45)로, LLM 판사가 전문가 대비 일관되게 관대한 채점 경향을 보임.

**국어 vs 사회, 학년별 gap_y 비교 읽는 법:**
- `grade = 중1, subject = 국어`의 gap_y 평균 = LLM 판사가 전문가보다 얼마나 낮게/높게 채점했는지
- 모든 셀에서 gap_y 평균이 비슷하면 → LLM 판사가 학년·교과를 가리지 않고 일관된 기준으로 채점
- 특정 셀만 gap_y가 크게 벗어나면 → 해당 학년·교과 조합에서 LLM 판사 편향 존재
